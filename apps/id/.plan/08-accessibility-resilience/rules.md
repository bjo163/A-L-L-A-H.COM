# Rules — Autonomous ID execution

1. Existing `dev` only; no new branches, main, or historical repositories.
2. Inspect current HEAD, source, shared exports, and dependencies before editing.
3. Work autonomously on reversible in-scope decisions; no routine user confirmation.
4. ARSY alone owns identity, credentials, authentication, sessions, tenant, roles, permissions, and first-owner atomicity.
5. No backend/schema/migration/cookie/CORS/DNS/proxy/TLS/secret/production/deployment changes.
6. Do not invent routes, fields, SDK methods, tokens, domains, or capabilities; verify source.
7. Reuse `@allah/sdk`, `@moonwitness/types`, `@moonwitness/ui`, and shared LUNAR CHRONICLES skin.
8. Never leak credentials, tokens, session IDs, secrets, internal tenant IDs, or raw provider diagnostics.
9. No false SSO/MFA/passkey/recovery/email-verification/security/deployment claims.
10. Async actions need pending, success-after-authority, failure, unavailable, and safe retry states.
11. Anti-slop: no generic SaaS hero, repeated centered cards, dashboard tiles, random gradients, icon salad, fake metrics, fake astronomy, dead buttons, or purposeless motion.
12. Preserve LUNAR CHRONICLES: personal observatory, lunar instrument precision, cartographic relationships, editorial archive, quiet wonder, functional legibility.
13. Semantic HTML, visible focus, keyboard support, associated errors, WCAG AA contrast, reduced motion, responsive behavior.
14. Add focused tests; never weaken tests. Run actual typecheck/build/relevant root gates.
15. Update task checkboxes and report with changed paths, commands, evidence, blockers, and commit.
16. Commit coherent batches to dev. Never force-push/rewrite history; reconcile remote changes safely.
17. Stop only for security/authority contradiction, missing server contract, irreversible data action, production boundary, or unavailable permission; record blocker and continue independent tasks.
