# UI and MoonFrame Skin Refinement Rules

1. Preserve existing authentication, SDK, business, routing, and user-owned worktree changes.
2. One semantic component engine; do not duplicate or replace Base UI, introduce a parallel token system, or add animation dependencies without an evidence-backed need.
3. Maintain tenant and data behavior unchanged; never invent metrics, status, progress, records, or celestial observations.
4. Use only approved existing app artwork. Do not generate logos, people, protected-work imitations, or new assets without explicit authorization.
5. Keep six skins distinct through their approved geometry, typography, composition, materials, and motion, not through palette changes alone.
6. Keep ambient motion decorative, low-distraction, user-pausable, and disabled under `prefers-reduced-motion`. Never animate fake system state.
7. Preserve semantic HTML, accessible names, visible focus, keyboard operation, touch targets, contrast, zoom/reflow, and non-color state cues.
8. Do not add a route, Skin Laboratory, API, backend, or GitHub issue changes in this task.
9. Record baseline and exact verification results. Do not claim a gate passed if it failed or was not run.
